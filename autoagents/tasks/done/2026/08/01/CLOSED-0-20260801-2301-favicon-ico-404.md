# Silence persistent /favicon.ico and /apple-touch-icon-precomposed.png 404s

## Source
- Docker incident (container `km0-web`, nginx static on `127.0.0.1:9180`).
- No GitHub issue; standing log noise.

## Problem / goal
nginx error log shows recurring 404s for browser/crawler default probes:

```
open() "/usr/share/nginx/html/favicon.ico" failed (2: No such file or directory) ... request: "HEAD /favicon.ico"
open() "/usr/share/nginx/html/apple-touch-icon-precomposed.png" failed (2: No such file or directory) ... request: "HEAD /apple-touch-icon-precomposed.png"
```

These repeat roughly every ~30 min across the whole day (18:18 to 22:55 UTC on 2026-08-01) and were already flagged as "prior unrelated 404s" during testing of a previous task on 2026-07-26, so this is a persistent standing incident, not a one-off.

Root cause: the site declares `favicon.svg` and `apple-touch-icon.png` in `src/layouts/Layout.astro`, but user agents that lack SVG-favicon support (and Apple/legacy clients) probe the well-known root paths `/favicon.ico` and `/apple-touch-icon-precomposed.png`, which do not exist. Result: log noise and a missing classic favicon for those clients.

## High-level instructions for coder
- Provide a real `/favicon.ico` so legacy/non-SVG browsers get a valid icon:
  - Add a `favicon.ico` under `public/` derived from the existing KM0 brand mark (`public/favicon.svg` / `public/apple-touch-icon.png`), keeping it consistent with the current brand system (see `.cursor/skills/km0-anti-slop-design/SKILL.md`; do not introduce a generic map-pin).
  - Optionally add `rel="icon" type="image/x-icon" href="/favicon.ico"` in `src/layouts/Layout.astro` alongside the existing SVG icon link so it is explicitly advertised.
- Handle `/apple-touch-icon-precomposed.png` (and the plain `/apple-touch-icon.png` root probe): either serve an asset at those exact paths or add a small nginx rule in `nginx/container.conf` that maps the precomposed probe to the existing `apple-touch-icon.png` (e.g. an exact-match `location` returning the existing asset), so Apple clients stop 404ing.
- Prefer the smallest correct fix. Do not change unrelated nginx blocks. Keep security headers and existing `location` rules intact.
- Bump site version once with `./scripts/bump-patch-version.sh` before renaming to UNTESTED- (per `.cursor/rules/site-version-bump.mdc`), since `src/` and/or `nginx/` change.
- Follow repo guards: `./scripts/check-no-em-dash.sh`, `./scripts/check-no-mailto.sh`.

## Implementation summary
- Added `public/favicon.ico`: a real multi-size ICO (16/32/48 px) rasterized directly from the existing KM0 lettermark geometry in `public/favicon.svg` (teal `#0F766E` field, off-white `#EEF0F2` "K0" mark). Generated with Pillow (already present on host; no new packages, no map-pin, brand-consistent).
- Advertised it in `src/layouts/Layout.astro` with `<link rel="icon" type="image/x-icon" href="/favicon.ico" sizes="16x16 32x32 48x48" />`, alongside the existing SVG icon and apple-touch-icon links.
- Added an exact-match nginx rule in `nginx/container.conf` mapping `/apple-touch-icon-precomposed.png` to the existing `apple-touch-icon.png` via `try_files`; no other blocks, security headers, or `location` rules changed.
- The plain `/apple-touch-icon.png` root probe already resolves to the real asset.
- No UI/layout/copy surface changed (icon asset + one head link + one nginx exact location), so no P/H/E/S/R/V scoring applies.
